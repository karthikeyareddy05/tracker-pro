# Android build

- **App id:** `app.floot.u774e670795c742c7be55c4d5d9f4279b` (unchanged from the original project)
- **App name:** Tracker Pro
- **Toolchain:** Capacitor 7, Android Gradle Plugin from the Capacitor template, JDK 21, compile/target SDK 35
- **Plugins:** `@capacitor-community/sqlite` (health records), `@aparajita/capacitor-secure-storage` (refresh token), `@capacitor/app` (back button), `@capacitor/splash-screen`, `@capacitor/status-bar`, `@capacitor/keyboard`

The `app/android/` platform folder is generated by `npx cap add android` and isn't committed. `scripts/build-android.sh` recreates it, then:

- generates icons and splash screens from `app/assets/`
- sets `versionCode` and `versionName`
- turns off Android cloud backup (`allowBackup="false"`)

## Build locally

```bash
export ANDROID_HOME=$HOME/Android/Sdk          # wherever your SDK lives
export VITE_API_BASE_URL=https://your-service.onrender.com
VERSION_CODE=1 VERSION_NAME=1.0.0 bash scripts/build-android.sh
# → dist-android/TrackerPro-1.0.0-debug.apk
```

Install on a phone with USB debugging: `adb install -r dist-android/TrackerPro-1.0.0-debug.apk`. You can also copy the file to the phone and open it.

To open the project in Android Studio after a build: `cd app && npx cap open android`.

## Debug vs. release

- **Debug APK** (built on every CI run): signed with the Android debug key. It's fine for installing on your own phone, but can't be published to Google Play.
- **Signed release APK**: create a keystore once and keep it safe. Losing it means you can't ship updates to the same app.

  ```bash
  keytool -genkeypair -v -keystore tracker-pro-release.keystore -alias trackerpro -keyalg RSA -keysize 2048 -validity 10000
  base64 -w0 tracker-pro-release.keystore   # copy the output
  ```

  Add these GitHub **secrets**:
  - `ANDROID_KEYSTORE_BASE64` (the base64 text)
  - `ANDROID_KEYSTORE_PASSWORD`
  - `ANDROID_KEY_ALIAS` (`trackerpro`)
  - `ANDROID_KEY_PASSWORD`

  CI then also produces `TrackerPro-<version>-release.apk`. For Google Play you would build an AAB instead: `npx cap build android --androidreleasetype AAB …`.

## What CI verifies on the emulator

The `android-smoke` job:

1. Boots an API 34 emulator and installs the APK.
2. Launches it, then force-stops and relaunches it.
3. Presses Back on the login screen.
4. Captures screenshots, the UI tree and logcat, and fails on any crash or if the app isn't running.

Screenshots and logs are pushed to the `ci-output/android-smoke` branch. Sign-in, SQLite persistence across restarts and offline use are covered by the unit, flow and end-to-end tests. Running them on a real device against your server is the remaining manual check: see the checklist in [TROUBLESHOOTING.md](TROUBLESHOOTING.md#manual-device-checklist).
